# Safety and Limitations

## What InboxPilot AI Does NOT Do

### No Automatic Email Sending
All generated draft replies are stored with `status = 'pending_review'`.
A human must explicitly approve each draft before it can be used.
The system has no mechanism to send email — this is by design.

### No Final Tax or Legal Advice
Draft replies generated by this system are templates and starting points only.
They contain `[TODO: ...]` placeholders requiring human input.
The tax question draft explicitly states it does not constitute formal advice.
All responses referencing tax matters must be reviewed and approved by a qualified professional before sending.

### No Claims of Professional Qualification
Neither the rule-based nor AI-generated drafts claim to be from a licensed tax advisor,
chartered accountant, or legal professional.
The safety enforcement layer (`src/safety.py`) automatically detects and replaces any such claims.

### No Real Client Data
The demo dataset contains entirely fictional clients, companies, and financial figures.
No real personal data, real financial data, or real email addresses are used.

### Demo Data Only
This prototype is designed for demonstration purposes.
It does not connect to any live email system, Gmail API, Exchange server, or inbox provider.

## AI Safety Boundaries (Phase 4)

### Validated Output
Every AI response is validated through `src/ai_validation.py` before use:
- Invalid categories default to `general_inquiry`
- Invalid priorities default to `medium`
- Missing fields are filled with safe defaults
- `requires_human_review` is always `True`, regardless of model output
- Confidence is clamped to `[0.0, 1.0]`

### Safety Enforcement on Drafts
Every draft (AI or rule-based) passes through `src/safety.py`:
- Risky guarantee phrases are replaced with measured alternatives
- Claims of email being sent are removed
- Licensed professional claims are neutralised
- API key patterns are redacted
- The `DRAFT FOR REVIEW` notice is appended if missing

### AI Suggestions Are Not Final Decisions
AI-enhanced processing provides a suggested classification and draft reply.
The office team reviews, edits, and approves all outputs.
The system never acts on AI output without human confirmation.

### Model Output Is Validated
The model's JSON response is passed through a strict validation layer.
Unrecognised categories, invalid priorities, missing fields, and out-of-range confidence scores are all corrected before the result is stored or displayed.

### Fallback Mode Avoids Dependency Failure
If the OpenAI API is unavailable or returns an unexpected response, the processor
automatically uses rule-based results. The application never fails because of an
unavailable third-party service.

## Known Limitations

| Limitation | Detail |
|------------|--------|
| Rule-based classification | Keyword matching; unusual phrasing may misclassify |
| AI classification | GPT-4o-mini may occasionally misclassify unusual email types |
| Confidence scores | AI confidence is self-reported by the model; not externally calibrated |
| Summary generation | Extracts key data points; not a true abstractive summarisation |
| Task extraction | Verb-pattern matching; complex multi-sentence tasks may split incorrectly |
| Deadline detection | Regex-based; ambiguous relative dates may not be captured |
| No attachments | Body text only — attachments are not parsed |
| English only | Classification patterns are English-language only |
| No threading | Each email is treated independently with no thread context |
| Single user | No multi-user auth; all drafts visible to any local user |
| Local SQLite only | No cloud sync; data lives in `data/inboxpilot.db` |

## Human Review Checklist

Before approving any draft:

- [ ] Verify the category and priority assigned are correct
- [ ] Read the full original email to confirm context
- [ ] Fill in all `[TODO: ...]` placeholders
- [ ] Confirm any financial figures or dates quoted are accurate
- [ ] For tax or legal matters, obtain appropriate professional sign-off
- [ ] Check the tone is appropriate for the specific client relationship
- [ ] Verify the processing mode (rule-based vs AI) and confidence level shown
- [ ] Review the safety note displayed in the processing metadata panel
